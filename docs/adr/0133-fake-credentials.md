# 133. Fake credentials

Date: 2026-09-28 · Status: accepted

## Decision
`POST /__control/credentials` issues:
- **S3 keys** shaped like R2's (32-hex access key id, 64-hex secret) with a
  scope: `object-rw` (read/write/list/delete in the listed buckets),
  `object-ro` (GET/HEAD/list), `admin` (every bucket, ListBuckets). Nobody can
  create or configure buckets over S3 — mirrors R2's bucket-scoped Object
  Read & Write token (ADR 95).
- **exe.dev VM tokens** — accepted by the proxy's token front (ADR 137).
- **OTLP bearer tokens** — once any active one exists, *direct* OTLP requests
  need `Authorization: Bearer <token>`; before that the receiver is open.

`DELETE /__control/credentials/:id` revokes; revoked credentials stay listed
and fail like unknown ones (`InvalidAccessKeyId`, 401). Secret material is
generated by the server and passed to the actor, returned once at issue time;
`/__control/state` never includes secrets.
